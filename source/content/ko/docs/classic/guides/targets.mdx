리스펙스는 [플레이그라운드](/ko/play)와 npm CLI에서 직접 실행됩니다. 워크플로의 다른 도구가 타깃 언어 코드를 만든다면, 그 결과물의 실행은 타깃별로 다릅니다. 아래는 타깃 언어 출력물을 각 도구로 실행할 때의 빠른 실행 팁과 흔한 주의사항입니다.

## Python
- `python file.py`로 실행합니다.
- 의존성은 가상환경 권장
- 값은 `print(...)`로 출력합니다.

## TypeScript / Node.js
- `tsx file.ts` 또는 `ts-node`로 실행합니다. 컴파일 후 `node file.js`로 실행해도 됩니다.
- ESM/CJS 차이에 유의(단일 파일 스니핏 권장)
- `console.log(...)`로 출력합니다.

## Go
- `go run .` 또는 `go run file.go`로 실행합니다.
- 다파일 프로젝트는 `go mod init …`가 필요할 수 있음

## Rust
- 크레이트 안에서는 `cargo run`으로 실행합니다.
- 단일 파일은 `rustc file.rs && ./file`로 실행합니다.
- 도구 체인은 최신으로 유지하세요.

## C / C++
- `clang file.c -O2 -std=c11 -o app && ./app`로 C 파일을 컴파일하고 실행합니다.
- `g++ file.cpp -O2 -std=c++17 -o app && ./app`로 C++ 파일을 컴파일하고 실행합니다.
- UTF‑8 로케일 설정, 개행/경로 차이 주의

## 공통 주의사항
- 인코딩은 UTF‑8을 기본으로 둡니다. 타깃에 따라 로케일과 인코딩 설정이 필요할 수 있습니다.
- 개행과 경로는 Windows와 POSIX가 다릅니다. 경로 결합은 표준 API 사용을 권장합니다.
- 마지막 값을 자동으로 출력하지 않는 타깃이 많습니다. `print`나 `console.log`로 출력하세요.

리스펙스 바우치 증거가 필요하다면 주변 호스트 코드가 어디서 실행되든 검사된 리스펙스 규칙과 영수증 및 재실행 아티팩트는 저장소에 함께 남겨두세요.
