Самый быстрый способ освоиться с Lispex это сразу выполнить код. Используйте
Песочницу для первого запуска без установки, npm CLI если у вас уже есть Node,
или автономный нативный бинарник для скриптов без зависимостей и генерации
квитанций Lispex Vouch.

## Установка или запуск в браузере

**Песочница.** Самый быстрый путь это [Песочница](/ru/play). Эталонный
интерпретатор, написанный на Rust и скомпилированный в WebAssembly, выполняет
код прямо в браузере, без установки.

**Нативный бинарник.** Установите автономный бинарник, если вам нужен
`lispex diff-receipt`, CLI без зависимостей или установка на сервер/в скрипт
без Node.

```bash
# macOS / Linux
curl -fsSL https://artifact.invalid/lispex/install.sh | sh
```

```powershell
# Windows PowerShell
irm https://artifact.invalid/lispex/install.ps1 | iex
```

Бинарники и контрольные суммы можно также скачать вручную на
[странице загрузок](/downloads).

**npm.** Используйте npm, если у вас есть Node 18+ и нужны `lispex run`,
`lispex verify` или `lispex replay`.

```bash
npm install -g lispex
```

Песочница и npm CLI используют WebAssembly-сборку того же эталонного
интерпретатора на Rust. Нативный бинарник запускает тот же интерпретатор
напрямую и является публичным путём генерации квитанций.

Проверьте установку:

```bash
lispex --version
```

## Первый запуск

Создайте файл `hello.lspx`. Первая строка это необязательный заголовок, который закрепляет версию входной грамматики.

```lispex
;! lispex 1.4

(define message "Hello, Lispex!")
message
```

Запустите файл.

```bash
lispex run hello.lspx
```

Песочница в браузере и CLI используют одну и ту же семантику эталонного интерпретатора.
В v1.4 эта общая поверхность стала шире: `apply`, `values`,
`call-with-values`, `modulo`, `string-append` и `number->string` проверяются
как в нативном интерпретаторе, так и в WebAssembly-сборке, которую используют
Песочница и npm-пакет.

## Проверка артефактов Lispex Vouch

Lispex Vouch добавляет проверяемый поток квитанций для корпусов правил, которые вы фиксируете в своих проектах. `lispex verify` офлайн проверяет дифференциальную квитанцию, а `lispex replay` сравнивает корпус решений с версией или набором квитанций.

```bash
lispex diff-receipt --input inputs/age-threshold.datum rules/age-threshold.lspx > receipts/age-threshold.json
lispex verify receipts/age-threshold.json
lispex replay decision-gallery --against decision-gallery/expected
```

Первую команду запускайте в нативном автономном бинарнике. Это публичный путь генерации квитанций, который пишет JSON `csk.differential-receipt/v0` в stdout. npm CLI может выполнять `verify` и `replay` для уже существующих артефактов, но не генерирует квитанции. Квитанция всё равно остаётся записью. Она не удостоверяет своё происхождение, не доказывает честность генерации, не показывает, кто и когда применил решение, не доказывает развёртывание и не заменяет эталонный интерпретатор.

## Следующие шаги

- Запустите ещё код в [Песочнице](/ru/play).
- Скачайте автономный бинарник на [странице загрузок](/downloads).
- Изучите [«Синтаксис»](/ru/docs/concepts/syntax), токены, литералы, базовые и производные формы, нормализацию.
- Напишите первые настоящие правила, одобрение возврата и ставку скидки, в руководстве [«Пишем решающие правила»](/ru/docs/guides/decision-rules).
- Посмотрите руководства о [модулях возможностей](/ru/docs/guides/capabilities) и [запуске на целевых средах](/ru/docs/guides/targets).
- Прочитайте [Lispex Vouch](/ru/docs/vouch) о проверяемом подмножестве, квитанциях, `verify` и `replay`.

Мы рады увидеть, что вы создадите на Lispex.
