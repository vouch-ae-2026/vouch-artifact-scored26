Это справочник по грамматике Lispex: **входной** грамматике S‑выражений и **детерминированным правилам нормализации** в Core AST. Эта страница описывает входную грамматику; семантика выполнения живёт в рантайме, а реальные программы можно запустить в [Песочнице](/ru/play).

> Область: только входная грамматика + нормализация. Пользовательские макросы/расширения чтения запрещены.

## 0) Заголовок файла (необязательно)

```lispex
;! lispex 1.4
```

## 1) Кодировка / пробелы / комментарии

- Кодировка: UTF‑8
- Пробелы: space, tab, CR, LF
- Комментарии: строка `; ...`, блок `#| ... |#` (вложенные)

## 2) Токены и литералы

### Символы (идентификаторы)
С учётом регистра, Unicode. Идея регулярного выражения: `[^()\[\]{}\s"';,`]+`. Зарезервированные слова нельзя связывать (см. ниже).

### Логические значения
```lispex
#t   #f
```

### Числа (вводные формы)
- Целые (десятичные): `0 | -?[1-9][0-9]*`
- Рациональные: `p/q` (q ≠ 0)
- Вещественные: `-?[0-9]+(\.[0-9]+)?([eE][-+]?[0-9]+)?`

### Символы‑литеры (Characters) / Строки
- Символы‑литеры: `#\a`, `#\space`, `#\x03B1`
- Строки: `"..."` с экранированием `\" \\ \n \t \r \xHH;`

### Списки / точечные списки / векторы / байтовые векторы
- Списки: `(a b c)`; точечные: `(a b . c)`
- Векторы: `#(a b c)`
- Байтовые векторы: `#u8(0 255 ...)`

### Семейство quote (сокращения чтения)
```lispex
'x      ⇒ (quote x)
`x      ⇒ (quasiquote x)
,x      ⇒ (unquote x)
,@xs    ⇒ (unquote-splicing xs)
```

## 3) Заголовок модуля (необязательно)

```lispex
(module <name>
  (export id ...)
  (import <name> ...)
  body ...)
```

`<name>` это символ или точечный путь (`util.string`). В этом заголовке нет rename/only/except. Файлы без модуля допустимы.

Примечание: этот заголовок необязателен и в руководствах не используется. Lispex выполняется напрямую в эталонном интерпретаторе. Примеры в руководствах оставлены минимальными на верхнем уровне. Инструменты могут сплющивать или игнорировать этот заголовок, когда готовят исходный код для другой цели.

## 4) Зарезервированные слова

```lispex
quote quasiquote unquote unquote-splicing
lambda if begin set! define let let* letrec
cond case and or when unless do
values call-with-values
call/cc dynamic-wind
module export import
```

Использование пользовательских макросов/расширений чтения приводит к ошибке: `define-syntax` `syntax-rules` `syntax-case` `let-syntax` `letrec-syntax` `#lang` `#;`.

## 5) Core‑формы

```lispex
(lambda (formals) body+)
(if test then else)
(begin e1 ... en)
(set! id expr)
(define id expr)
(define (f params) body+)
(let ((id expr) ...) body+)
(letrec ((id expr) ...) body+)
(quote datum)
(quasiquote template)
(values expr*) (call-with-values producer consumer)
(call/cc proc) (dynamic-wind before thunk after)
```

`call/cc` создаёт одноразовое восходящее escape-продолжение. Первый вызов
помечает его использованным до начала раскрутки. Любой повторный вызов, включая
вызов из `after` формы `dynamic-wind` во время той же раскрутки, завершается
ошибкой E340 (`escape continuation is no longer active`). Текущий профиль не
поддерживает повторный вход в продолжение.

## 6) Производные формы

```lispex
(define (f a b) body...) ⇒ (define f (lambda (a b) body...))
(let* ((x e1) (y e2) ...) body)
  ⇒ (let ((x e1)) (let* ((y e2) ...) body))
(cond (t1 b1...) ... (else e...))
  ⇒ (if t1 (begin b1...) (if t2 (begin b2...) ... (begin e...)))
(case key ((k11 k12 ...) b1...) ... (else e...))
  ⇒ (let ((t key)) (if (eqv? t (quote k11)) (begin b1...) ... (begin e...)))
(and) ⇒ #t, (and e1) ⇒ e1, (and e1 e2 ... en) ⇒ (if e1 (and e2 ... en) #f)
(or)  ⇒ #f, (or e1)  ⇒ e1, (or e1 e2 ... en) ⇒ (let ((t e1)) (if t t (or e2 ... en)))
```

---
Примечание: нормализация `case` использует `eqv?`, как в R7RS и эталонном интерпретаторе. Сравнение идёт через скрытый интринсик `eqv?`, поэтому пользовательское переопределение не влияет на результат.
