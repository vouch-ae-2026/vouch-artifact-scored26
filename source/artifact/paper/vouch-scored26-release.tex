\begin{abstract}
This record reports the implemented authenticated-native boundary for Vouch.
It separates structural acceptance from authenticated origin, binds Native
evidence to a consumer-supplied trust policy, and promotes evidence to a
decision only after transcript agreement and release signability checks.  The
reported fixture, workload, mutation, and performance values are rendered
from digest-verified owner reports after the signed release chain is checked.
The result is evidence about observed agreement over an explicit checked
surface; it is not a proof of policy correctness or whole-language semantic
equivalence.
\end{abstract}

\section{Problem and threat model}

Native-shaped JSON is not evidence of native origin.  A verifier must first
apply bounded canonical parsing, select an already-authorized Ed25519 key from
an out-of-band consumer policy, verify the DSSE signature, and only then
interpret the authenticated payload.  Bridge evidence remains a distinct
artifact class and cannot be promoted through the Native decision boundary.

The threat model includes artifact-class confusion, context substitution,
payload/envelope mismatch, a path replaced after command entry, a source inode
mutated after its digest check, cross-release mixing, and a caller attempting
to reach a release key with an unsigned or non-signable result.  The model does
not assume an honest application after a capability has been returned.  It
also excludes freshness, signer compromise, dishonest input collection, legal
fitness, and the correctness of the policy itself.

\section{Mechanism and implementation}

The checked lane evaluates the same normalized source and immutable input in a
reference evaluator and a separately implemented Meaning Environment
evaluator.  Invocation-bound, one-shot trace tokens prevent a caller from
assembling a receipt from serialized transcripts.  Issuance requires complete
terminals, byte-identical observable traces, an empty diagnostic set, a final
decision value, a release build, and a non-mutant build before the key handle
is resolved.  Refusals before key resolution are tested with a counting key
provider and perform zero key operations.

Verification uses a fixed order: resource and canonical gates; closed policy
and envelope schemas; selected-key authorization; signature verification;
payload canonicality and schema; intrinsic receipt consistency; and expected
context comparison.  Successful verification yields authenticated evidence,
not a decision.  A separate promotion step checks agreement, completed
terminals, trace completeness, the final decision, and release metadata.

The release lifecycle is acyclic.  A signed deterministic descriptor $D$
binds the source commit, archive, executable, toolchains, dependency manifests,
and exact-reproduction results.  A trusted Linux outer driver authenticates
$D$ before extracting an immutable private snapshot, executes phase 1, and
constructs the clean-run report $Q$.  Phase 2 derives and signs observation
$R$ from $D$, $Q$, and the exact owner-report buffers; publication record $P$
names $D$ and $R$.  Phase 3 verifies $D\rightarrow Q\rightarrow R\rightarrow P$,
replays the final derivations, verifies the paper-source snapshot, renders this
document, and emits terminal report $S$.

\section{Limitations}

The two evaluators share numeric and value substrates, so common-mode errors
remain possible.  A receipt establishes observed agreement for the recorded
source, input, profile, engine, budgets, and transcript boundary.  It does not
establish semantic equivalence for Lispex in general, independent witnessing,
freshness, fairness, legality, generation honesty outside the signed release
boundary, or protection against a dishonest consumer that ignores the API.
Unsalted public hashes do not protect low-entropy real-world records.  Public
welfare-shaped inputs in this artifact are synthetic and generated by the
committed workload procedure; they are not drawn from people, case files,
production logs, or administrative datasets.

\section{Artifact availability}

The release set consists of the source archive, signed descriptor, clean-run
report, signed reproduction observation, publication record, resolved paper,
and terminal publication report.  Authorization comes from the consumer's
out-of-band trust policy; the adjacent public-key record and unsigned
publication record are distribution and indexing aids, not trust roots.
